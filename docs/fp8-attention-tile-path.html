FP8 KV attention · kernel hypothesis

The K8 tile may lose before it saves bytes.

K8/V8 reads less HBM than K16/V8. It can still be slower if BF16-Q/FP8-K operand preparation becomes the limiting stage of the fused tile loop. The claim is testable. The old "all scores wait for K dequant" picture is not.

Microtests that decide it

Use one pinned FlashInfer build, record the selected kernel and cubin, and vary one thing at a time. Otherwise the benchmark merely proves that dispatch tables exist.

M0 · CONTROL

Four dtype cells

K16/V16, K8/V16, K16/V8, K8/V8. K-only and V-only deltas separate the two sides.

M1 · TRANSFORM

Blackwell modes

Compare BF16-Q/FP8-KV Full, KOnly, and SeparateKv. Log the exact selected kernel.

M2 · CACHE STATE

Warm and cold

Run L2-warm and HBM-cold variants. A byte-driven delta should grow when HBM dominates.

M3 · TILE TAX

Preparation-only probe

Same K8 load and layout, with and without the transform. Include a K16-load control. Measure steady-state tile interval.

M4 · SHAPE SWEEP

Find the crossover

Sequence 128–64K; batch 1–64; head dimensions 64/128/256; GQA ratios from 1:1 through 8:1.

M5 · PROFILER

Count the hidden cost

DRAM/L2, conversions, tensor pipe, long scoreboard, barriers, shared memory, registers, occupancy and TMA overlap.

M6 · NATIVE NARROW

Try the escape routes

FP8-Q × FP8-K and Blackwell MXFP8 block-scaled QK versus the plain E4M3 transform path.

M7 · QUALITY

Make K8 admissible

Ordinary K8/V8, pre-bias K8/V8, K16/V8. PPL, KL, top-1, NIAH and long autoregressive decode.

M8 · SERVING

Close the loop

Kernel latency, ITL, throughput, memory capacity and admitted concurrency. A microkernel win alone is not deployment.
