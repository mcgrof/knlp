FP8 KV attention · measurement plan

Measure the K8 tile against the byte savings.

K8/V8 reads one fewer K byte per element than K16/V8. Measure whether BF16-Q/FP8-K operand preparation lengthens the steady-state tile interval enough to erase that HBM saving.

Run the deciding microtests

Pin one FlashInfer commit, record the selected kernel and cubin, and vary one factor at a time.

M0 · DTYPE CONTROL

Run four storage cells

Measure K16/V16, K8/V16, K16/V8, and K8/V8. Use K-only and V-only deltas to separate the two sides.

M1 · TRANSFORM

Sweep Blackwell modes

Compare BF16-Q/FP8-KV Full, KOnly, and SeparateKv. Log the exact selected kernel.

M2 · CACHE STATE

Measure warm and cold

Run L2-warm and HBM-cold variants. Track how the K8/V8 delta changes as HBM pressure rises.

M3 · TILE COST

Isolate preparation

Hold K8 loads and layout constant. Toggle the transform. Add a K16-load control. Measure the steady-state tile interval.

M4 · SHAPE SWEEP

Find the crossover

Sweep sequence 128–64K, batch 1–64, head dimensions 64/128/256, and GQA ratios 1:1 through 8:1.

M5 · PROFILER

Count the limiting resources

Collect DRAM/L2, conversion, tensor-pipe, scoreboard, barrier, shared-memory, register, occupancy, and TMA metrics.

M6 · NATIVE NARROW

Test native QK paths

Compare FP8-Q × FP8-K and Blackwell MXFP8 block-scaled QK against the plain E4M3 transform path.

M7 · QUALITY

Gate each cache format

Run ordinary K8/V8, pre-bias K8/V8, and K16/V8 through PPL, KL, top-1, NIAH, and long autoregressive decode.

M8 · SERVING

Validate the full stack

Measure kernel latency, ITL, throughput, cache capacity, admitted concurrency, and output quality.

Apply explicit decision rules

ATTRIBUTE THE GAP TO K PREPARATION

Require the K-only dtype delta, transform-mode delta, and profiler stalls to move together while V remains fixed.

REJECT THE K-PREPARATION EXPLANATION

Reject it when K8/V16 matches K16/V16, transform modes converge, or the latency delta follows DRAM bytes without an on-chip stall signal.

DISPATCH BY OPERATING POINT

Use dual dispatch when K8/V8 wins in HBM-dominated regimes and K16/V8 wins in preparation- or occupancy-dominated regimes.

Improve symmetric FP8

SCHEDULE

Pipeline the transform

Double-buffer K tiles, specialize producer and consumer warps, place V preparation next to PV, and remove extra shared-memory round trips.

INSTRUCTION PATH

Use native narrow QK

Quantize Q for QK where quality permits. Test FP8 MMA and Blackwell block-scaled MXFP8 with hardware scale consumption.

CACHE LAYOUT

Write the preferred layout once

Store K, V, and scales in the matrix unit's block-scaled and swizzled layout. Avoid per-token decode transcoding.

NUMERICS

Store the pre-bias residual

Keep the fixed K bias exact. Quantize the token-varying residual. Compare pre-RoPE reconstruction with post-RoPE residual plus score correction.

FALLBACK

Retain K16/V8

Dispatch to native K for partial-RoPE and other key distributions that fail the symmetric quality gate.

SERVING POLICY

Optimize served goodput

Choose the format from quality, kernel time, cache capacity, and admitted concurrency rather than kernel latency alone.

Preserve run provenance

Record the GPU SKU, clocks, driver, CUDA or ROCm version, FlashInfer commit, JIT URI, cubin hash, transform mode, page layout, warmup policy, timing method, and raw profiler reports for every row.
