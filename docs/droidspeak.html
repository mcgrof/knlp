Our DroidSpeak baseline selected four receiver layers out of 32 and passed its held-out quality rule on a paper-named Mistral adapter pair. The receiver reused sender KV before and after that interval. It did not translate every KV tensor and did not train a new checkpoint.

This result validates the partial-recomputation mechanism in one process. It does not reproduce the paper's remote transfer pipeline or its end-to-end speedups.

What DroidSpeak changes

The key-value (KV) cache stores the attention keys and values for prior tokens. Two models can have the same architecture and token vocabulary but different weights, such as two adapters on one base model. Their caches are not normally interchangeable. DroidSpeak profiles where the receiver must regain its own representation, then recomputes only one contiguous layer interval.

The sender's layer-input embedding at layer 14 starts receiver recomputation. The receiver produces new KV inside the interval. Sender KV remains outside it.
1 · Sender prefillCache the whole prompt except its final input token. Record KV and possible transition embeddings.
2 · Offline profileTest all contiguous two-layer-boundary intervals and measure answer F1 and local time to first token.
3 · SelectChoose the fewest receiver layers that stay within 5% of full-receiver profile F1.
4 · Receiver handoffAssemble reused and recomputed KV, then process the final input token to obtain receiver logits.

The cache covers the whole prompt, not only the passage. Holding back the last input token is part of the generation contract. The receiver processes that token after the hybrid cache is ready and uses its output logits for the first generated token.

The profiler chose four receiver layers

The profile used 50 HotpotQA multi-hop question-answering records. It tested 137 intervals on two-layer boundaries, including full reuse and full receiver prefill. Token F1 measures normalized word overlap with the reference answer on a scale from 0 to 1. The selection rule allowed at most a 5% relative F1 drop from full receiver prefill.

QUALITY DECISION: PASS

The selected interval reached 109.1% of the full-receiver F1 point estimate and exceeded the required floor. Direct reuse reached only 78.4% of full receiver and failed the floor.

The point estimate above full receiver is not evidence that DroidSpeak improves model quality. This is a small, single-split evaluation, and the selection used a related profile set from the same dataset.

WHAT THE RESULT SUPPORTS

For one same-base adapter pair, direct cache reuse was poor, while a profiled four-layer receiver interval restored held-out quality under the stated rule. The full-receiver interval produced bit-exact KV tensors relative to ordinary receiver prefill.

WHAT IT DOES NOT SUPPORT

It does not establish arbitrary cross-family sharing, paper-scale generalization, remote-transfer speedup, production readiness, or an exact reproduction of the authors' interval.

LMCache can carry the cache, but it does not supply DroidSpeak

A separate control used one LMCache server and two same-model serving processes. The second process retrieved 7,168 cached tokens, and both processes produced the same completion. This verifies shared same-model transport.

VERIFIED TRANSPORT

LMCache can move and retrieve a compatible KV cache across serving processes. The cache server reported the retrieval in 0.003 seconds in this bounded control.

MISSING CROSS-MODEL BRIDGE

Stock LMCache does not select a DroidSpeak interval, transfer the arbitrary transition embedding, run only that receiver interval, or assemble sender and receiver layers into one cache.

System role: LMCache is a useful transport substrate. A production integration still needs model-pair namespaces, compatibility checks, transition-embedding transport, partial receiver execution, hybrid-cache assembly, and transfer/recomputation overlap.

Source and claim boundary

The public code contains the in-process mechanism, exhaustive interval profiler, exact full-recompute audit, scoring, deterministic data split, and LMCache transport control. Raw run records are not part of the public code tree.
