The filesystem
is not the tax.

Moving a KV cache between GPUs through NVMe does not require giving up a filesystem. On the same drive, the same payload and the same io_uring path, writing to a file on XFS or ext4 lands within a few percent of writing to the raw namespace. The cost that does show up is elsewhere.

The comparison covers two implementations that both reach storage — the vLLM storage handoff connector over NIXL, and LMCache raw_block driving the device itself — against three targets each, with NIXL GDS as the baseline.

The GDS baseline is host-staged here. With the IOMMU translating, gdscheck reports NVMe : compat and warns that GDS is not guaranteed to work functionally or performantly with iommu=on/pt. cuFile therefore falls back to staging through host memory rather than doing peer-to-peer DMA. The number is real and worth having as a baseline, but it is not a GPU-direct number, and labelling it as one would be wrong.

What this does and does not establish

ESTABLISHED

A file on XFS or ext4 carries the KV cache at essentially the raw-device rate on this drive, through the same io_uring path, with the dma-buf command-size ceiling applied. Keeping a filesystem is not what costs throughput.

NOT ESTABLISHED

Nothing here says what GDS would do with the IOMMU in passthrough, where cuFile could use peer-to-peer DMA. That is a different measurement on a differently booted host, and it is the honest comparison to make next.

Measured on one host, kernel 7.3.0-rc3-dmabufrc3-mp, 2026-09-24. Every run addressed the drive through /dev/disk/by-id and verified device identity before writing. Reproduce with make defconfig-pd-nixl-xfs and its siblings in knlp.
