Context reuse · checkpoint inference · October 2026

Reusable context,
typed by its consumer.

A learned key/value prefix, a document-vector bank, and a query’s soft memory tokens can share a storage contract. Each still needs its own model interface and cache identity.

This work extends the Learned Prefix Cache (LPC) architecture toward Memorilla’s latent memory. The shared catalog and LMCache host-artifact adapter now restore document banks for released Memorilla inference. Controlled replay separates storage correctness from numerical batch sensitivity. LPC keeps its own model attachment path.

Current result: the document-bank adapter matches original checkpoint predictions in the tested controls. Explicit scheduling makes the ported offline comparison repeatable. Paper scores and batch-independent generation are separate checks; read the checkpoint results and replay controls.

01 / The shared contract

Separate storage from model execution.

A context artifact is a versioned tensor payload plus the information needed to use it correctly. Its immutable ID binds the payload digest, representation, producer, and compatible consumers. File location and working-copy residency can change while that semantic identity stays fixed.

Learned prefix

prefix_kv

Per-layer key and value tensors for a particular model. Preserve exact logical positions, layer/head geometry, rotary-position settings, dtype, layout, and padding.

Document bank

document_embeddings

Vectors produced by a pinned encoder and preprocessing pipeline. A compatible memory reader consumes the bank; it does not enter the decoder’s key/value cache directly.

Soft memory tokens

input_embeddings

Vectors in the decoder’s input space. Bind their reader, bank, question, prompt placement, and positions. Prefill must still turn the assembled input into layer-specific key/value state.

The file registry implements import, resolve, load, working-copy eviction, and restore. It validates safetensors before synchronizing payload files and directories, then publishes metadata in a synchronous SQLite transaction. Missing, corrupt, or incompatible required artifacts fail explicitly. Existing cartridge connector APIs remain unchanged.

02 / Sharing prospects

Reuse the stable representation.

The useful sharing boundary depends on what produced the bytes. The following are architectural prospects; CPU file reuse does not establish physical GPU aliasing or an engine cache hit.

ArtifactPotential reuseIdentity that must stay bound
LPC key/value prefixMany requests to the same compatible decoder can attach one trained artifact. Avoid training or reconstructing it on a cache miss.Checkpoint bytes, model weights, positions, geometry, layout, and ordered composition with the request.
Memorilla document bankDifferent questions can reuse the same query-independent collection. New or changed source material needs a new version.Source content, encoder revision, preprocessing, namespace, and compatible reader.
Memorilla readoutAn identical readout can be restored when its complete dependencies match. A shared bank alone is insufficient.Actual soft-token bytes, question/readout dependencies, reader checkpoint, decoder, template, and placement.
Derived decoder key/value statePotential reuse after exact prompt-embedding prefill. This bridge is not implemented here.All preceding inputs, their order, model identity, positions, and the derived payload.

An ID gives consumers a common object to resolve. It does not make vectors interchangeable across models, enforce access control, or make independently trained prefixes composable. Namespace is part of identity; an actual service still needs authorization. Multiple runtime users, resident-memory deduplication, and cache-key propagation require separate engine tests.

05 / Papers and interfaces

Memorilla and REFRAG shorten context differently.

Memorilla reads a query-independent document-vector bank with a learned, query-conditioned module. Its released Qwen configuration emits 16 input-space memory tokens for a frozen decoder. Reading the whole selected collection is part of that method; replacing it with top-k retrieval would change the algorithm.

REFRAG, from Meta and academic collaborators, encodes fixed token chunks, projects their vectors into decoder input space, and can expand selected chunks back to text. Its reconstruction stage freezes the decoder; later continual pretraining unfreezes it. Its mixed-input path therefore needs the corresponding trained decoder, encoder, projection, and policy.

QuestionMemorillaREFRAG
Reusable unitDocument embeddingsEncoded chunks
Query-time contextFixed-size learned memory readoutOrdered mixture of compressed chunks and expanded text
Decoder dependencyFrozen decoder paired with the trained readerDecoder aligned through the paper’s training recipe
Context budgetFixed memory-token countDepends on chunk count, compression, and expansion decisions

These are method differences, not a matched accuracy or speed comparison. The papers use different models, tasks, training, and controls. Neither paper’s headline performance is a measured result of this implementation.

06 / Engineering target

Make context durable, compatible, and reusable.

Our target is a common lifecycle for context representations: publish verified bytes, resolve an immutable handle, load the representation its consumer expects, and recover it after eviction or restart. Training remains a producer’s separate responsibility. A missing LPC must not launch training, and storage must not disguise document vectors as layer KV.

Preserve each control.

Establish the real LPC engine/checkpoint baseline and the unmodified Memorilla decoder path. Keep engine-version changes separate from artifact/storage changes.

Attach context through the right interface.

Use the existing LPC attachment for KV and exact template-aware input embeddings for Memorilla. Retain engine ownership of allocations and scheduling.

Qualify sharing and restore.

Test equal-length different payloads, different questions over one bank, native and external cache keys, and actual inference after GPU eviction and process restart. File parity is the prerequisite already explored.

Measure the complete cost.

Separate encoding, readout, serialization, storage completion, transfer, prefill, and decode. Compare matched tensors and cache states before making a storage or end-to-end speed claim.

A possible REFRAG adapter belongs at the chunk-bank and mixed-input boundaries, with its own typed metadata. Whether that adapter is worthwhile needs a separate compatibility and quality evaluation. It is not part of the CPU pass reported here.

09 / Reproducible comparisons

Control when requests enter the engine.

A V1 engine process can execute a request while its caller is still submitting the rest of the batch. That timing can change numerical execution batches and native prefix reuse, even when every prompt embedding is identical. Diagnosis verified 4,096 unchanged prompt deliveries. Complete-batch admission restored parity while retaining multiprocessing, weights and cache residency.

Port and LMCache controls now default to KNLP_MEM_SCHEDULING="inprocess", following vLLM’s offline guidance. The original-author profile preserves upstream runtime behavior. The memorilla-port-batch-replay and memorilla-lmcache-batch-replay presets instead retain multiprocessing: pause scheduling at level zero, enqueue the complete call, resume scheduling, then wait for completion. They require the corresponding public APIs and an idle, exclusive offline engine.

The recorded port uses Torch 2.9.1 with ROCm 6.4, Transformers 4.57.6 and a locally patched V1 engine derived from vLLM 0.18.1rc1. Catalog modules have their own source pin; their tests do not certify a complete fork-engine build.

Eight fresh 1,024-request runs qualify the repaired source without diagnostic admission hooks. The default-runtime native/adapter control has 51 string differences. All six repaired runs agree exactly in all 15 pairwise comparisons, including native versus adapter, repeat runs and in-process versus multiprocessing admission. Decoder prefix caching, asynchronous scheduling and chunked prefill remain enabled. This qualifies the recorded port runtime; it does not certify a stock engine build or every hardware/backend combination.

Different neighboring questions and document-bank padding can still change the reader or decoder’s floating-point results. The memorilla-port-reference and memorilla-lmcache-reference presets isolate one request at a time and disable decoder prefix caching. Document-bank residency and the real restore path remain active. These are numerical reference controls; their scores need not equal a batch-32 run.

Both single-request runs complete the same 384-request trace. Native and adapter predictions and all collated-input, reader-output and decoder-prompt tensor hashes match at every position. Repeated inputs have no tensor or string variants in either run. The adapter performs 384 bank loads with eviction after every request and no resident hits. These results qualify the reference on the recorded port runtime; they do not make batch-32 or cross-backend outputs equivalent.

10 / System qualification

Stress the storage contract and keep the mmap baseline.

The new port passes a complete 240-package dependency check with stock public vLLM 0.29.0, Torch 2.13.0 and Transformers 5.20.2 on Python 3.13. A normal LMCache wheel matches all 721 Python files in its pinned source, with no unexpected modules. Its supported NO_GPU_EXT=1 build includes native host extensions; this qualification covers the host-artifact path. The original Memorilla model and evaluation source remain unchanged. GPU KV kernels, optional backends and all eight paper scores on this newer runtime remain separate gates.

The resolved dependency lock and reproduction instructions keep this port separate from the original-author preset. No training or kernel modification is required.

Concurrent checkpoint reads preserve the answers.

Eight diagnostic controls compare original mmap and LMCache with one and eight bank-fetch clients on PubMedQA and NarrativeQA. Storage workers fetch banks before each ordered batch; the original collator, learned reader and decoder preserve request order. These are parallel storage clients feeding one offline engine, with batch size four, in-process scheduling, eager execution and decoder prefix caching disabled. They are not independent online decoder clients.

The campaign completes 3,168 checkpoint requests in 22 workers, plus two deliberately interrupted workers. All 14 selected comparisons match inputs and answer strings exactly. All ten instrumented comparisons also match nonempty collated-input, reader-output and decoder-prompt hashes. Both paths abort four active decoder requests, drain them and reproduce the control after retrying on the same engine. Separate workers are killed with four requests still active; fresh processes reproduce their controls.

Memory limits must include the page cache.

A separate CPU matrix completes 56 cases across all 100 PubMedQA banks and 355 NarrativeQA banks. Every one of 251,914 completed reads matches the expected full bank bytes, shape and dtype; 6,134 queued reads cancel. Running reads drain. Cases cover one and eight clients, hot and initially cold files, 2/8 GiB process-tree limits, two order-balanced repeats, and 32-client sharing. There are no out-of-memory kills.

The large working set contains about 2.41 GiB of tensors. Initially cold 8 GiB cases peak at about 3,122 MiB charged memory for mmap and 3,590 MiB for the adapter, including setup. Both use the Linux page cache. Under a 2 GiB limit, both trigger real reclaim and remain correct; measured storage reads rise to about 6,152/6,689 MiB, respectively. The adapter's 64 MiB arena therefore does not bound total host memory. Cloned tensors, runtime allocations and file pages all matter.

File residency is measured with mincore. Cold controls evict only owned payload files, never the global page cache. Already-hot file pages can be charged to an earlier process group, so hot-case accounting alone cannot establish physical memory use. The small working set fits either limit and shows no reclaim. A limit is not itself proof of pressure.

Mmap wins the hot CPU comparisons. The adapter's modest throughput lead in the eight-client pressure case comes with worse p95 latency and more storage reads; the one-client pressure case favors mmap. This is no general storage-speed win. One-bank sharing does work: 32 clients produce one adapter load and 8,191 or 1,023 resident hits. That demonstrates process-local sharing, not one host allocation shared across processes.

11 / Prepared reads

Reuse validated metadata on repeated reads.

The host adapter caches immutable file read plans, typed manifests and validated tensor layouts. Resident reads check the consumer and stored header, then create fresh views of the actual allocation. Each payload reload still compares the current catalog and hashes every loaded byte. The collator still receives its own tensor copy. The original mmap baseline and full-collection reader remain available.

Metadata caches default to 1,024 entries, separately from the payload arena. Entry budgets do not bound caller-held plans, active references, cloned tensors or the Linux page cache. A bounded capacity wait reuses the admitted plan while another lease releases memory; it does not repeat metadata parsing on every retry. Its deadline does not interrupt file operations already running. Catalog transactions close their SQLite connections after each operation.

A CPU replay completes 264,192 exact bank reads in 48 processes. Three process blocks rotate native mmap, old adapter and prepared-read adapter order on one host, with hot relevant files and a full-byte validating consumer. Each normal case uses all 100 PubMedQA or 355 NarrativeQA banks, one or eight clients, a 64 MiB arena and one Torch CPU thread. The table gives the median of three process medians.
