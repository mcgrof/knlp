Inference systems · Agent context retention

KMesh

Keep what comes back. Restore it on demand.

Agents leave long contexts idle while they wait for a tool or a user, and then come back to them. KMesh studied how a serving system can keep the saved model state for those contexts, the key/value (KV) cache, and restore it instead of computing it again. The research closed on November 23, 2026. Two directions remain open: one is research, the other is integration.

Read the two directions  ·  Read why KMesh closed

Two open directions

Both directions come from the agentic workflow introspection, which read four released agent traces. Related agents share little: in a Claude Code corpus, launches of four or more children are 2% of all launches. Contexts that sit idle between turns carry much more. In the same corpus, long main-agent requests that resume a minute or more after a wait carry 15.7% of the main agent's input tokens. In the GitHub Copilot release, long-context turns that resume after five or more idle minutes carry 17–19% of the prompt tokens the deployment recomputes. During each wait, the serving system decides what to do with the context. The first direction uses the wait itself. The second lets the party that sees the agent tell the cache what to keep.

1. Use the tool-call wait (research)

When the model calls a tool, its session stops until the result comes back. The context up to the call is complete and already cached, but the resumed turn must still compute the result's tokens over that whole context before it can answer. The FreeInference agentic trace records how long these waits are. In both released weeks, 69–75% of tool-result tokens arrive after a wait of 1 s or more, and a quarter after 5 s or more. Calls to the file-read tool carry the largest share of result tokens.

Dynamo's speculative prefill already uses the end of a turn to warm the next turn's known prompt. The open question is what more a serving system can prepare during a tool wait, so that the resumed turn computes less after the result arrives, and whether that work still pays when other sessions share the GPU. KMesh has no result on it yet.

The wait runs from the end of the response that made the call to the start of the session's next request, so it includes the harness time around the tool. Calls made in one response share it. Token counts use the release's tokenizer, not a served model's. The trace scripts reproduce the table with tool_wait.py.

2. Execute kv.retain hints in LMCache (integration)

Serving engines now accept a typed, versioned kv_hints envelope on each request; vLLM merged it in September 2026 (vLLM #53423). Its proposed kv.retain action lets an orchestrator that knows the workflow name the token ranges a session will use again, each with a priority and a duration, so that the cache evicts other blocks first (vLLM #38514, open). This gives the retention question on this page to the party that can see the agent. The vLLM proposal applies the hint to vLLM's own GPU prefix cache. LMCache holds the same context in host memory and on storage, and it reads no KV hints today.

LMCache is a storage tier for vLLM and also plugs into SGLang's cache. A kv.retain reader in LMCache would let any of these producers keep a waiting session's context in host memory or on storage, not only in GPU memory. Dynamo is one user. llm-d, an agent runtime that sends its own hints, and a gateway that passes on a client's cache lifetime are others. The SGLang path also needs LMCache's SGLang integration to read the hints that SGLang now forwards. This page does not propose how LMCache should act on a hint.

A producer must also choose each hint's duration. The idle-context cost model compares the cost of keeping one context in host memory or on storage for 5 minutes to 72 hours with the cost of computing it again once, and uses the return times in the Copilot release to estimate how often the kept context is used. Its prices, speeds and return rates are editable assumptions, not measurements.

Faster GPUs make computing a context again cheaper, so restoring a context stays faster only while each saved byte replaces enough prefill work. The cache-reuse projection models that race for one context as GPUs, storage paths and model architectures change. Its rates are editable assumptions, not measurements. The traces put agent contexts on the side that favors restoring: the resumed contexts are long, and in an attention model the prefill work per saved byte grows with context length.

KMesh is closed

We closed the KMesh research on November 23, 2026. It began as a study of state shared between related agents. The introspection of released agent workflows showed that such sharing carries little volume, and moved the question to each session's own context between turns. That work found a gap in how LMCache stores a resumed session: a chunk that nothing wrote made the first request after an eviction compute everything after it again. The fix is in review as LMCache PR #6396. In its GPU test, that request's first token comes 30% to 80% sooner.

The agentic workflow introspection records the experiments, what they establish, the negative results and why each line of work closed. The agent workloads page gives the trace sources and counts.
