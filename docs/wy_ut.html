Numerical linear algebra → GPU kernels

WY / UT without the 1970s prerequisite course

Why does a modern linear-attention paper suddenly talk about Householder matrices, WY representations, triangular solves, and blocked kernels? Because the same systems problem has been solved repeatedly for seventy years: take many tiny dependent matrix updates and reorganize them into work the hardware can execute efficiently.

1. The primitive

Start smaller than Householder: a rank-one update

Take a column vector u and a row vector vᵀ. Their outer product uvᵀ is a matrix, but a severely constrained one. It reads the input along one direction and writes along one direction. Its rank is one.

A = I − uvᵀ

I means “do nothing.” Subtracting uvᵀ means “do nothing except for this one directional correction.” That is why identity-minus-rank-one matrices appear everywhere: they are cheap structured changes to a state.

The interesting part begins when you multiply several of them. With two factors:

(I − u₁v₁ᵀ)(I − u₂v₂ᵀ)
= I − u₁v₁ᵀ − u₂v₂ᵀ + u₁(v₁ᵀu₂)v₂ᵀ

The last term is the nuisance and the opportunity. Factor 1 interacts with factor 2 through the scalar v₁ᵀu₂. With many factors you get many ordered cross-interactions. WY and UT are ways of collecting those interactions instead of replaying every factor against the big matrix one by one.

2. The classical special case

A Householder reflector is an actual mirror

H = I − 2vvᵀ / (vᵀv)

Pick a vector v. The matrix H flips the component parallel to v and leaves every perpendicular component unchanged. Geometrically, it reflects across the hyperplane perpendicular to v.

The key property is orthogonality: HᵀH = I. Lengths do not get stretched. That makes long sequences of Householder transformations numerically attractive.

Why QR cares: choose the reflector so one column is rotated onto a coordinate axis. Every entry below the diagonal in that column becomes zero in one shot.

A = QR

Q is the product of the orthogonal reflectors. R is upper triangular. Once the problem is triangular, solving it is cheap by substitution.

This is not abstract decorative algebra. It became a workhorse for least squares, linear solves, and the transformations used inside eigenvalue algorithms.

Do not collapse these terms: a rank-one update is the broad category. I − βkkᵀ is Householder-shaped. It is a true reflector only for the special coefficient that makes the map orthogonal. DeltaNet lives in the broader Householder-like category, not generally in the exact-reflection category.
3. What problem was Householder solving?

Oak Ridge needed reliable matrix computation, not a pretty reflection

Alston Householder joined Oak Ridge in 1946 and moved into numerical analysis there, working on differential equations and matrix problems. He also pushed Oak Ridge toward electronic computing. The ORACLE computer was completed in 1953; the first program used to test it was a Givens eigenvalue program. That detail is useful because it shows the environment: matrix eigenproblems were machine workloads, not textbook ornaments.

Householder’s 1958 paper gave an orthogonal route for triangularizing a nonsymmetric matrix. The practical value was stability on finite-precision computers. You could transform the problem aggressively without also magnifying numerical error by arbitrary scale factors.

By 1965, Businger and Golub published Householder-based least-squares software. Least squares is what you use when observations outnumber unknown parameters: orbit fitting, survey adjustment, calibration, experimental regression, and countless other “infer parameters from noisy measurements” jobs. This is how a reflector becomes infrastructure: the application never asks for a mirror; it asks for the fitted parameters.

4. The missing middle

EISPACK, LINPACK, BLAS, and LAPACK were not four versions of one thing

This is where most modern explanations become hostile to anyone who was not already doing scientific computing in 1983. The names refer to different layers of a numerical-software ecosystem.

BLAS is an interface contract, not “that library from Intel”

BLAS means Basic Linear Algebra Subprograms. The official interfaces were defined through published papers. Netlib provides reference implementations. Hardware and software vendors provide tuned implementations. That separation is the whole point: LAPACK can say “multiply these matrices” without knowing whether the machine underneath is a Cray vector processor, an x86 CPU, or something else.

Level 1
vector ↔ vector
dot products, scaling, axpy
Level 2
matrix ↔ vector

Level 3
matrix ↔ matrix
high reuse; GEMM territory

The jump from Level 2 to Level 3 is not just “a bigger operation.” Matrix-matrix multiplication lets the implementation reuse tiles of data many times after loading them. That raises arithmetic intensity. On machines where moving data is expensive relative to multiplying it, this is the difference between feeding the arithmetic units and starving them.

Why LAPACK had to exist

The LAPACK documentation says the older LINPACK/EISPACK memory-access patterns did not exploit newer multi-level memory hierarchies well. The fix was to reorganize algorithms so block matrix operations sit in the inner loops. In other words: keep the numerical method, change its granularity.

That is exactly where WY enters QR. Householder QR naturally hands you one reflector at a time. LAPACK wants a block update that can become Level-3 BLAS. WY/compact-WY is the representation that bridges those two facts.

And the LINPACK benchmark?

Separate the package from the benchmark. Dongarra describes the benchmark as essentially an accident: the 1979 LINPACK Users’ Guide included timings for a standard linear solve so users could estimate runtimes. The timing table grew into a machine-comparison tradition and, much later, the TOP500 lineage. LINPACK the solver package and LINPACK the benchmark are related historical objects, not synonyms.

5. The 1987 complaint

Bischof and Van Loan wanted Householder algorithms to contain more matrix-matrix multiplication

The abstract of the 1987 WY paper is unusually direct. The authors wanted a representation of products of Householder matrices that made Householder algorithms “rich in matrix-matrix multiplication,” because matrix-matrix multiplication was becoming the operation of choice on high-performance machines. They tested QR with the representation on the FPS-164/MAX.

Here is the systems problem. Suppose a panel produced b reflectors and they all need to update a much larger trailing matrix C.

Naive application
C ← H₁C
C ← H₂C
⋮
C ← H_bC

Walk over the large matrix again for every reflector. Lots of small rank-one work.

Block application
Q = H₁H₂…H_b = I + WYᵀ

QC = C + W(YᵀC)

Represent the product once, then use matrix-matrix operations on the large target.

W and Y are just names. They are not acronyms. This is one of those historical naming choices that later generations must simply endure.

The signs and exact definitions of T vary across papers and libraries. Do not let that hide the invariant structure: a large product is represented by skinny factors plus a small triangular interaction object.

Why a triangle?

Order. Reflector 1 can affect what reflector 2 sees; reflector 2 cannot travel backward in time and affect how reflector 1 was defined. The interaction graph is one-way. One-way dependence is triangular algebra wearing a different hat.

7. What blocked QR actually does

WY does not make the entire QR factorization parallel

This distinction is easy to miss and matters directly when comparing classical QR with ML chunking.

  1. Factor a narrow panel. Householder vectors are generated one after another. There is still sequential dependence inside the panel.
  2. Accumulate those reflectors. Build the compact representation, including its small triangular factor.
  3. Apply the block to the trailing matrix. This is the large expensive part, now expressed through Level-3 BLAS.

In LAPACK, routines such as xLARFT form the triangular factor for a block reflector and xLARFB applies it. xGEQRT is one blocked QR route. This is why most people have used WY-style machinery without ever seeing the name “WY.” It was absorbed into plumbing.

8. Why ML rediscovered the problem

DeltaNet turns tokens into a sequence of Householder-like state maps

DeltaNet updates a matrix-valued memory using a delta-rule correction. One common orientation is:

Sₜ = Sₜ₋₁ (I − βₜ kₜkₜᵀ) + βₜ vₜkₜᵀ

The important factor is I − βₜkₜkₜᵀ. It has the same identity-minus-rank-one shape as the classical reflector machinery, but βₜ is learned, so this is generally not an orthogonal reflection.

The 2024 DeltaNet parallelization paper explicitly exploits the WY representation to represent products of these structured state transitions without materializing a full matrix-sized product for every token. It groups tokens into chunks so much of the state update and output computation can be done as matrix multiplications.

So why do people now say “WY/UT”?

The 2024 paper foregrounds the WY representation. In later implementation and explanation of DeltaNet, Songlin Yang describes the UT transform as the triangular reorganization used to parallelize the recursive construction of the transformed update vectors. Modern implementations therefore often discuss both names around the same chunkwise kernel family.

That distinction is worth keeping: WY is the broad compact-product representation used in the paper’s derivation; UT is a closely related triangular-solve representation that is especially convenient for implementing the dependent transformed factors efficiently. “WY/UT kernel” is systems shorthand for this family, not evidence that two unrelated algorithms were duct-taped together.

9. The real boundary

The trick works because the recurrence is affine in the state

Each DeltaNet step is affine in S: multiply the old state by a matrix, then add a term. Products and compositions of affine maps remain affine. That closure is what lets a chunk be summarized by fixed factors computed from the token parameters.

S' = S A + B    →    affine in S

If the write rule becomes genuinely nonlinear in the current state, the coefficients of the next transformation depend on the very state you are trying to summarize. There is no fixed finite WY/UT factorization of the same kind waiting to be discovered.

This is the precise reason the Trellis case on the linear-attention study is different. It can still obtain chunk parallelism by freezing/linearizing the state at a chunk boundary, but that is an approximation to the nonlinear recurrence, not the exact classical WY closure.

11. Translation dictionary

Terms that otherwise make papers unnecessarily miserable

reflector
An orthogonal matrix that mirrors vectors across a hyperplane.
Householder-like
Has the identity-minus-rank-one shape but need not have the coefficient that makes it an exact reflection.
panel
The narrow block of columns currently being factored in blocked QR.
trailing matrix
The large remainder to the right of the panel that must be updated.
blocking
Reorganizing an algorithm to do larger coarse-grained operations, especially matrix-matrix work.
GEMM
General matrix-matrix multiplication, the canonical Level-3 BLAS operation.
compact WY
A block-reflector representation that stores the Householder vectors plus a small triangular factor.
triangular solve
Solving TX=B when T is triangular, cheaply by substitution; libraries provide highly optimized versions for many right-hand sides.
UT transform
An accumulated-Householder representation written with a triangular solve; closely related in purpose to compact WY.
