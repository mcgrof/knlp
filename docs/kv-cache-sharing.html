Cross-model KV-cache sharing · evidence map · October 2026

Two ways to hand a KV cache to a different model.

KV-Lingo translates cached keys and values into the receiver's representation. DroidSpeak keeps most sender layers and recomputes one receiver-layer interval. Both try to avoid a full receiver prefill after a model change. They use different model pairs, data, controls, and decision rules.

Evidence in one sentenceOur unrestricted Qwen3-4B/8B KV-Lingo reproduction did not qualify, while our same-base Mistral-adapter DroidSpeak mechanism passed its held-out quality rule; neither result yet proves a production cross-model cache-sharing system.

Each effort answers a different question

A KV cache stores the attention keys and values for prior tokens. Ordinary reuse requires the same model weights and cache layout. Cross-model reuse needs a method to repair the representation mismatch.

Effort 1 · KV-Lingo

Translate each model's missing cache spans

Learn separate linear key and value maps for corresponding receiver layers. Keep one cache line per model. When a model returns, translate only the conversation spans that it did not produce itself.

Tested here: repeated ten-turn switching between Qwen3-4B and Qwen3-8B on 32 CoQA (Conversational Question Answering) conversations.

UNRESTRICTED USE NOT QUALIFIED

Effort 2 · DroidSpeak

Reuse most layers and recompute a receiver window

Profile one contiguous receiver-layer interval. Reuse sender KV outside it, inject a transition embedding at its start, and compute native receiver KV inside it.

Tested here: one handoff between two Mistral-7B adapters, with 50 profile and 50 disjoint held-out HotpotQA multi-hop question-answering records.

What the current evidence says

Token F1 measures normalized word overlap with the reference answer on a scale from 0 to 1. Each study compares its treatment only with its own matched controls.

KV-Lingo outcome
0 / 4

Forward/reverse checkpoint pairs passed the full rule across both starting models and both native references.

All eight 4B-start comparisons failed at least one gate. The 8B-first signal is a narrower development result, not a qualified deployment.

DroidSpeak outcome
4 / 32 layers

The selected receiver interval scored 0.3149 held-out F1 versus 0.2887 for full receiver prefill and a required floor of 0.2742.

Direct cache reuse scored 0.2263. Some receiver recomputation was necessary.

SUPPORTED

Cross-model cache repair can preserve quality for the tested same-base DroidSpeak adapter pair. Learned KV translation acquired useful structure but did not meet our unrestricted Qwen3-4B/8B rule.

NOT YET SUPPORTED

Neither study proves arbitrary cross-family cache reuse, a universal checkpoint, production reliability, or a full-path cost saving.

ARTIFACT BOUNDARY

KV-Lingo produced trained pair-specific maps, but those tested tensors are not published. DroidSpeak produced no trained checkpoint; its reusable artifact is the selected interval and runtime configuration.

Could DroidSpeak improve KV-Lingo?

Yes as a research design, but not as a drop-in patch for the current Qwen3-4B/8B pair. DroidSpeak offers a way to spend native receiver compute where translation error is most damaging, while KV-Lingo can translate the cache outside that interval.

Profile translated-cache quality across candidate receiver-layer intervals. Treat full translation as the zero-recompute control and full receiver prefill as the correctness control.
For each interval, translate the boundary hidden state into the receiver width, recompute native receiver KV inside the interval, and use translated KV outside it.
Select the smallest interval that passes untouched quality data, then measure transfer, translation, recomputation, storage, and time to first token end to end.
WHY IT COULD HELP

Our KV-Lingo result shows a large first 4B→8B handoff deficit. Local native recomputation could reset accumulated representation error before the receiver decodes. DroidSpeak's interval profiler supplies a direct way to find where that reset has the best quality-to-compute tradeoff.

WHY IT IS NEW WORK

The current DroidSpeak path assumes equal hidden shapes and aligned layers. Qwen3-4B and Qwen3-8B do not satisfy that contract. A hybrid needs a trained hidden-state bridge, explicit layer alignment, and tests that the recomputed interval can consume translated boundary state safely.

Most credible first test: start with two adapters on one base architecture, where DroidSpeak already works, and add KV translation outside the selected interval only if direct reuse remains weak. Test a cross-width Qwen3 pair after the same-shape hybrid passes exact controls.

LMCache is the transport layer, not a third repair method

LMCache can share a compatible cache between serving processes. Our control retrieved 7,168 same-model cached tokens and produced an identical completion. Cross-model use still needs KV-Lingo translation or DroidSpeak partial recomputation in the receiver runtime.
