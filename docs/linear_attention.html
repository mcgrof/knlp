Measured, not just diagrammed

Linear attention and bounded memory, in ordinary English

Dense attention remembers old tokens by keeping their keys and values. That memory grows with context length. The models on this page try a different bargain: keep a fixed-size matrix state, update it as tokens arrive, and read from that state later. We implemented Trellis and compared it with reference DeltaNet, Gated DeltaNet, and GatedDeltaProduct layers under matched runs.

The result is simpler than the old version of this page made it sound. Gated DeltaNet is the best model we measured at the scales we could afford. Trellis's nonlinear write did not close that gap. But the reason is not “nonlinear writes are bad.” Our final correctness audit showed that the write comparison changes when the outer training gradient changes. The paper's much larger 790M / 30B-token result remains untested here, so it is parked, not refuted.

1. Start with the problem

What “bounded memory” means

In ordinary causal attention, each new token produces a key and a value. Future tokens may need them, so inference keeps those key/value vectors in the KV cache. Double the context length and, roughly speaking, you double the amount of cached history.

A bounded-memory model does not keep one record per old token. It compresses history into a fixed-size state matrix. The state changes every token, but its dimensions do not grow with the sequence.

Dense attention

Store past keys and values. A new query can look back at them directly.

memory ∝ context length
Bounded recurrent memory

Fold old information into a fixed matrix state and query that state.

memory state size = fixed
The trade-off: dense attention keeps detailed token-level history but pays memory and bandwidth as context grows. A bounded state caps the memory footprint, but every write must decide what to preserve, overwrite, or forget.
2. The basic writer

DeltaNet treats the state like a tiny online associative memory

Let S be the state matrix. For one token, let k be the direction used to address memory, v the value we want that key to retrieve, β the write strength, and q the query used to read the state.

S ← S + β(v − Sk)kᵀ
o = Sq

The term Sk is what memory currently returns for key k. The error v − Sk says how wrong that association is. The update writes back a correction along k. This is the delta rule used as a fast-weight memory.

Write-before-read simply means the current token updates the state first and then reads from the updated state. Nothing mystical is hiding in that phrase.

The important systems property is that this update is affine in the state: after the token-derived quantities are known, the old state appears only linearly. That is what allows several token updates to be combined exactly into a chunk.

3. What changes between the models

Same fixed-state idea, different write rules

DeltaNet

Uses the delta-rule correction above. The state update is affine, so a chunk can be evaluated exactly with the classical WY/UT-style reorganization.

Gated DeltaNet

Adds a learned decay α so old memory can fade:

S ← αS + β(v − αSk)kᵀ

Still affine in S, so it keeps the exact chunking property.

Trellis

Turns the inner memory write into a nonlinear gradient step. If z = Mw, it transforms z through a nonlinear φ and writes using the gradient of that inner objective.

That extra state-dependent nonlinearity is the important difference. It changes both the math of chunking and the training gradients.

GatedDeltaProduct takes a different route: it stays affine in the state but uses multiple structured Householder-like steps per token to make overwrite operations more expressive.

6. Why DeltaNet gets the easy chunking algebra

“Exact chunk parallel” means the chunk gives the same answer as token-by-token execution

A chunk is just a short consecutive group of tokens. If every token update has the form

S' = SA + B

with A and B fixed after the token quantities are computed, then several updates compose into another affine update. The whole chunk can be summarized without changing the answer.

DeltaNet and Gated DeltaNet have exactly this property. Their rank-one transitions can be collected using the same family of algebra described on the WY/UT page: a compact low-rank representation plus a small triangular dependency solve turns many token steps into matrix multiplies.

Trellis's normalized-SiLU write is different. Its Jacobian depends on the current state through z = Mw. Once the coefficients of the next update depend nonlinearly on the state being updated, the original-state WY/UT factorization is no longer an exact representation of the recurrence.

Careful claim: this does not prove that every nonlinear recurrence is impossible to parallelize exactly. It says the particular fixed finite WY/UT factorization used by the affine-state models no longer applies. Special nonlinearities can have other representations.

The fused kernel fixes Python overhead, not the algebra

The first Trellis implementation was mostly paying for a Python launch-bound loop. A fused Triton kernel keeps the per-head state tile resident, performs the LayerNorm-SiLU VJP in the program, and uses a hand-derived backward.

The fused path raises the full mixer from about 120.7k to 769.8k tok/s, a 6.4× gain on A100. The same kernel delivered an 8–12× improvement on the W7900. That makes the experiment practical, but the remaining gap is a measured implementation gap, not a proven lower bound for all nonlinear memories.

At decode, the trade changes again. A fixed state does not grow with context, but it is still a dense read-modify-write object every token. Whether it beats a modern GQA KV cache depends on state size, precision, batch, context, and hardware.

7. Trellis training has two separate choices

Forward approximation and training gradient are not the same knob

This distinction is the most important correction from the final audit. The old page mixed two decisions together.

Choice A: what state does the within-chunk forward use?

The affine models can combine the true token-by-token recurrence exactly. Trellis cannot use the same factorization for its nonlinear write, so the paper freezes the state at the start of the chunk. With that state fixed, the local write response becomes linear enough to evaluate in parallel with a scan.

That gives chunk-parallel execution, but it computes a chunk-start linearization of the nonlinear recurrence rather than the exact running-state recurrence. The approximation error depends on how far the state moves inside the chunk and how nonlinear the write is.

Choice B: does the outer loss differentiate through the inner gradient step?

Trellis writes memory by taking a gradient of an inner objective. The outer language-model loss can either differentiate through that gradient or treat it as a fixed value.

First-order

Detach the state used to form the inner correction. Cheaper. The forward values are unchanged, but the second-derivative path is removed.

Full bilevel

Differentiate through the inner gradient step. This keeps Hessian-vector-product terms. Same forward values; different parameter gradients.

A dispatcher bug originally made the configuration claim “bilevel” while the chunked backends were actually training first-order. Because the forward values are identical, ordinary forward checks did not expose it. The modes are now explicit and tested for equal forwards but different gradients.

The final factorial is why “nonlinear write bad” was too simple

WriteFirst-orderFull bilevel
identity / linear write~253 PPL, 3/4 clean244.5, 3/3 seeds, best stable result
SiLU nonlinear write251.6, 3/3 seedsonly 1/3 seeds completed at full higher-order strength

Under first-order training, SiLU is slightly ahead. Under the full bilevel objective, the linear write is the best stable arm and the full-strength SiLU higher-order gradients are unstable. So there is no honest write ranking without stating the gradient semantics.

A tempered version scales only the higher-order gradient path:

u = u_detached + ρ(u_live − u_detached)

The forward update is unchanged. With ρ = 0.5, every seed completed and the result beat first-order training by a small, consistent margin.

8. What the Trellis paper reports

The paper wins at scales we did not reproduce

The paper does compare Trellis and Gated DeltaNet below 790M. An earlier version of this page got that wrong by confusing the 125M component-ablation table with the separate head-to-head table.

Published settingTrellisGated DeltaNetResult
125M, Pile-2k head-to-head10.87 PPL11.31Trellis ahead
790M / 30B, C420.2821.40Trellis ahead by 1.12 PPL

The separate 125M component ablation reports Trellis 10.87, no chunking 10.75, no forget gate 11.28, TTT 11.44, DeltaNet 11.58, and a linear-φ write with the inter-pass map held nonlinear at 11.65. That last row is a clean write-only ablation in the paper: linearizing the write costs about 0.78 PPL there.

Our largest faithful family comparison is nowhere near the paper's 790M / 30B regime. The correct statement is therefore: we found no Trellis advantage at our reachable scale; the paper reports one at larger scale; we did not test whether that crossover is real.

9. The write ablations

The original “2×” control is useful, but it is not a clean write-only experiment

The first control kept the Trellis shell and switched φ to identity. At matched learning rate and tokens it reached 127.9 PPL versus 248.4 for the nonlinear arm, nearly a 2× difference.

But that old harness tied two activations to one configuration field: the write nonlinearity φ and the inter-pass map f. Setting φ = identity therefore linearized both. It also used the old stale-chunk-16 approximation. So the 2× number is a joint φ/f control, not an isolated measurement of the write.

After the two activations were separated, the clean write-only associative-recall test held f at LN-SiLU and varied only φ. The linear write reached 1.00 recall while the nonlinear write reached 0.62 across three seeds. That supports the direction on this synthetic task. The paper's language-model ablation goes the other way at 125M: nonlinear Trellis beats the linear-write control by 0.78 PPL.

So keep the evidence scoped. The old 2× number shows that the linearized shell was much easier to optimize in that run. The clean recall test favors the linear write. The paper's 125M language-model ablation favors the nonlinear write. The final bilevel factorial says gradient semantics can flip the ranking again.

The nonlinear activation also tolerated a much higher learning rate in the original small run. The identity write diverged at 1e-3 and above while the nonlinear version remained trainable, so the nonlinearity was clearly buying optimization stability even when it did not buy lower loss in that experiment.

10. Another expressivity bet

GatedDeltaProduct solves overwrite nicely, but Gated DeltaNet still won our C4 pilot

GatedDeltaProduct adds multiple structured Householder-like steps per token while keeping the state transition affine. The extra steps are designed to perform richer overwrite operations without giving up exact chunking.

On the synthetic overwrite/binding grid, GatedDeltaProduct-2 scored 1.000 and Gated DeltaNet 0.996. Both solved the task. The interesting question was whether the extra recurrence work helped ordinary language modeling.

In the width-matched C4 pilot, model width 512, ten layers, sequence 2048, 20M tokens, three seeds:

The Gated DeltaNet advantage over GatedDeltaProduct-2 is about 0.039 nat/token, roughly 4% in PPL, across the three seed sets. This is an early-training pilot, not a converged verdict. The DeltaProduct paper reports a thin advantage at much larger scale under a compute-favored comparison, and its parameter-matched control shrinks to about 0.14 PPL. Our result says only that the larger recurrence did not pay off in this pilot.

11. What we actually concluded

Close the experiment, keep the useful pieces

Keep
  • Bounded memory beat matched dense attention at every PG19 context length tested.
  • Gated DeltaNet is the trusted matched-state baseline for downstream decode and KV work.
  • The fused Trellis kernel is reusable systems work even though the architecture lost the comparison.
  • The WY/UT boundary is useful: affine state updates admit the exact classical chunking route; state-dependent nonlinear writes need something else.
  • The final audit exposed a general lesson: forward semantics and gradient semantics must be tested separately.
Park, do not declare dead

The paper's 790M / 30B scale claim. We never trained that regime. A faithful 125M / 2.4B reproduction would be the next meaningful scale test, but every cheaper family comparison we ran favored Gated DeltaNet, so the line is closed unless a new reason makes that run worth the cost.

Bottom line: for the scales and recipes tested here, the best bargain is still a linear delta-rule memory with a good forget gate. Trellis's nonlinear writer did not beat that baseline, and GatedDeltaProduct's extra overwrite machinery did not beat it in our pilot either. That is an empirical conclusion, not a theorem that expressive writes can never win.

12. Audit trail

The conclusions changed as bugs and confounds were removed

2026-08-04: the correctness audit found that the flag selecting the bilevel objective never reached the chunked backends. Closure-era chunked runs had trained first-order. After explicit state-mode × gradient-mode semantics and higher-order reference checks landed, the write ranking became gradient-dependent. The tempered higher-order path at ρ=0.5 was stable in all seeds and gave a small consistent gain.

2026-07-27: the write activation φ and inter-pass map f were decoupled. The earlier 2× identity result was reclassified as a joint φ/f control. A clean write-only associative-recall rerun kept f fixed and still put the nonlinear write behind the linear one on that task.

2026-07-21: the page retired the claim that Trellis was compared with Gated DeltaNet only at 790M, removed over-strong statements that nonlinearity proves no exact parallel method can exist, and scoped the DeltaProduct result to its actual pilot regime.
