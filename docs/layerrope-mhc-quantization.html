The hypothesis worth testing

The hypothesis is that LayerRoPE’s depth-dependent gains could improve tolerance to weight quantization, either alone or combined with mHC. This study tests that possibility; it is not a result established by the LayerRoPE paper.

One possible mechanism is that a depth-conditioned gain schedule changes weight ranges or redistributes sensitivity to rounding. Multiple residual streams and constrained routing might also distribute perturbations. They might instead increase storage or move sensitivity elsewhere. Neither intuition establishes a gain; the test must compare clean loss, damaged loss, bytes, and compute.

Weight screens. These post-training weight-rounding experiments are evaluated after dequantization. The separate cache tests keep weights unchanged. The mechanisms are composable. Their gains need not add. A depth code changes the update rule at a layer; it does not attach an immutable layer identity to each contribution after streams have been mixed.

The write code and carry code, precisely

For four streams, use a balanced phase code:

c(φ) = [cos φ, sin φ, −cos φ, −sin φ]
s = minᵢ(βᵢ, 2 − βᵢ)
β′ = β + 0.5 s c(φ(ℓ))

Here β is the original vector of write coefficients in [0, 2]. The bounded correction preserves that range. M-O (V01) uses the ordered layer schedule. V02 applies a fixed shuffled layer lookup. V03 uses the middle-depth phase everywhere. The schedule has four learned scalars across the attention and MLP paths.

V30 instead adds 0.5 × c cᵀ / 2 to the carry logits before Sinkhorn normalization; its write coefficients stay unchanged. V30-S shuffles the phase lookup before forming the outer product. V30-C uses the middle-depth phase. The outer product has rank one and is invariant to a π phase shift, so its depth code has different symmetries from the write code.

The Birkhoff-geometry interpretation of mHC (Audio Summary) can help reason about mean and difference modes of an exactly doubly stochastic carry map. It does not make finite-iteration routing exact, guarantee quantization robustness, or turn a mixed residual stream into a record of each layer’s contribution.

Discovery and confirmation were kept separate

A 32-variant screen varied code amplitude, placement, phase, basis, read/write/carry insertion, and learned frequency. Stage A screened at 1,000 steps; Stage B continued the selected rows to 2,000 steps, using three discovery seeds on a W7900.

V20, a learned-frequency write variant, was the raw Stage B leader for training and quantization: primary CE 2.610010 and INT4 CE 2.528025, versus 2.617378 and 2.551336 for mHC. An unresolved historical numerical miss prevented qualification. It was not silently replaced in the discovery ranking, and it was not independently confirmed.

The frozen confirmation nominees were V30 for training and V02 for quantization. Their ordered, shuffled, and constant controls formed seven rows. Stage C used eight fresh paired seeds, 4,000 steps, and reserved document-disjoint evaluation arrays. All 56 trajectories completed on the frozen H100 runtime. Stage D, the proposed deeper-model test, stayed disabled because no nominee passed.

Coverage mattered more than the tested depth codes

All 56 checkpoints passed both block-only INT4 and block-only INT3 under the +0.1-nat damage limit. None passed all-matrix INT4, all-matrix INT3, or group-128 INT4. This pattern holds across every confirmed architecture row.

The block-only path quantizes about 31.925% of parameters. It leaves both the token embedding and the language-model output head unquantized. The all-matrix path covers about 95.878%. This localizes the large observed penalty to the broader coverage change; it does not identify which excluded matrix dominates, or establish additive error attribution.

Quantizer definition and coverage

The primary screen uses symmetric per-row max-absolute scaling with nearest rounding, without calibration or retraining. Each case starts again from the same clean checkpoint. All eligible matrices means the backbone embedding and linear weights; normalization gains and routing/code controls are not integer-quantized.

qmax = 2b−1 − 1
scale = max(|w|) / qmax
ŵ = scale × clamp(round(w / scale), −qmax, qmax)

Zero-scale rows are handled without division by zero. Group-128 repeats the max-absolute calculation within groups of 128 columns, padding the last group as needed. Scales are FP32. The block-only case selects backbone layer linears, excluding both the embedding and output head. The weights are dequantized for CPU model evaluation. INT2 in the screen has three symmetric levels; it is not a four-level asymmetric codebook.

The quality threshold is a per-checkpoint CE increase no greater than 0.1 nat, equivalent to a perplexity ratio no greater than exp(0.1), about 1.105. This is the frozen engineering tolerance, not a proof that the change is perceptually negligible.

Equal-bit precision and unequal K/V precision are separate tests

Neither M-O nor mHC enabled a lower passing equal-bit cache precision. Equal-bit means that keys and values use the same number of bits. The original sweep also tested symmetric K8/V4, K4/V8, K16/V4 and K4/V16, but it did not cover unequal 2/3-bit pairs or unequal affine pairs. An equal-bit minimum alone cannot establish the smallest passing cache in bytes.

This is a separate intervention from the weight experiments above: model weights stay unchanged, while attention keys and values are quantized and dequantized before use. Cache damage is the extra cross-entropy (CE) over that same checkpoint’s clean result.

The quality metric, model and quantizer names

Cross-entropy (CE) is the mean negative natural logarithm of the probability assigned to the actual next GPT-2 token in held-out TinyStories text. Evaluation supplies the true preceding tokens. It makes 131,072 predictions in 512 adjacent 256-token windows, resetting context at each window. It does not grade generated answers.

PPL = exp(CE)
PPL(K3/V2) / PPL(K3/V3) = exp(Increment)

Lower perplexity (PPL) means better next-token prediction on this story distribution. An extra 0.03 nats corresponds to about 3% higher perplexity. A lower starting loss can leave mHC better in absolute prediction quality even when its incremental quantization penalty is larger.

These are custom LLaMA-style decoders trained from scratch on TinyStories, with width 128, FFN width 352, two attention heads, a 50,257-entry GPT-2 vocabulary, untied embedding/output weights and a 256-token context. The three-seed cohort trains on 4.096 million tokens; the separate eight-seed cohort uses 8.192 million.

“Symmetric” describes signed quantization levels centered on zero, not equal bit widths. K3/V2 uses unequal K/V precision with that codebook. The affine alternative shifts its levels using a floating minimum and a scale. At two bits, it uses four levels, while this signed quantizer uses three. What the cache fake quantization actually does

Keys are quantized after token RoPE and values before attention. Each token/head derives its own statistics across 64 channels, avoiding future-token scale leakage. Queries remain unchanged. Every retained and current token is quantized; there is no unquantized residual window and no extra training.

Both quantizers use FP32 arithmetic for quantization and restore BF16 values for attention. The symmetric path uses max-absolute scaling and 2b−1−1 as its positive limit. The affine path uses a floating minimum and range/(2b−1). Thus symmetric 2-bit has three levels, while affine 2-bit has four and needs extra metadata. The full grid includes unequal precision in both directions, plus K-only and V-only controls at every tested bit width.

At 32 layers, an ideal packed affine 2-bit cache would use 3,072 bytes per token, including FP32 scales and minima, compared with 16,384 bytes for BF16 K/V. That is a theoretical 5.33× reduction. The simulator actually uses dequantized tensors, so no physical memory reduction or packed-kernel speedup was measured.

Qualification checks compare scalar quantization with an independent reference, verify token-local statistics, compare incremental cached attention with full-window and explicit-softmax references, require bit-exact noquant logits on each real checkpoint, and verify unchanged model-state hashes after the sweep.

Numerical qualification remained a separate gate

V01, V02, V03, and V30 retained numerical misses in the prescribed historical/confirmation scope. V00, V30-S, and V30-C passed that scope. A successful checkpoint resume or a good final loss cannot clear an earlier tolerance failure.

Some discrepancies were small in absolute terms. One retained V01 comparison missed by about 8.27×10−9 against a 5.46×10−6 reference, giving relative error 0.001514 above the 0.001 threshold. Agreement in FP64 for the same finite function points to sensitivity between FP32 evaluation graphs; it does not justify changing the frozen tolerance after seeing results.

Keep two questions separate: whether the implemented 20-step Sinkhorn function and its derivative agree with a same-function oracle, and whether that finite map approximates an ideal converged projection. Replacing the operator with a much longer solve changes the experiment.

Interpretation and conclusion

The full K/V grid found useful unequal allocations, but no architecture-specific reduction in minimum passing bytes. Signed K3/V2 saves 14.3% of ideal bytes versus signed K3/V3 at 16/32 layers, with additional loss. It matches the byte cost of affine K2/V2. For the K3/V3 → K3/V2 change, mHC has a larger loss increment than residuals at both depths in every tested seed. Ordinary residual, mHC and M-O reach the same overall byte floor in their matched comparisons. The early training rankings also did not yield a confirmed winner.

CLEAN MODEL QUALITY

mHC improved clean loss in the matched residual-control cohort, especially at 16 and 32 layers. Better absolute loss after quantization is useful, but it is not evidence of lower rounding sensitivity.

WEIGHT QUANTIZATION

Which matrices were rounded had a much larger measured effect than storing the four depth scalars in BF16. Block-only INT3 preserved quality by leaving most parameters unquantized, with a substantial byte cost.

KV-CACHE QUANTIZATION

Both the quantizer and the K/V bit allocation affect damage at a fixed byte cost. Unequal precision improves some within-quantizer choices, while adding mHC or M-O does not lower the measured overall byte floor.

The practical conclusion is to compare clean quality, extra quantization damage and total bytes together. Do not treat block-only weight INT3 as a three-bit model, or cache fake quantization as a measured serving-memory or speed improvement. Full LayerRoPE cache behavior, longer contexts, and separate embedding/head sensitivity remain open questions. No depth-scaling or subliminal-learning defense follows from these language-model results.

Author feedback: full gains and three beta initializations

Follow-up protocol; no new measured result yet. Shikhar Srivastava highlighted the need for both magnitude and rotation at the input and output sites. The author’s reference code applies an output gain directly to the branch; it does not require an output normalization. The implementation audit found two distinct cases: the historical MNIST adaptation had only an input gain and a zero initial magnitude slope, while the TinyStories LayerRoPE models already had input/output magnitude and rotation gains at both attention and MLP sites. The language-model results above must not be described as an input-only implementation.

The follow-up adds an independent MNIST output gain and tests equal initial magnitude and rotation slopes at −1, −0.5 and 0. These are initial values; the schedules remain trainable. MNIST retains LayerNorm centering and bias, so it is an adaptation rather than an exact copy of the reference language model.
