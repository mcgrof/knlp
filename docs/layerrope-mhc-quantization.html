Give each layer a different way to read and write

A residual stream is the running state carried through a network. Each attention or feed-forward block reads that state, computes an update, and adds it back. A gain multiplies each channel: it can strengthen, weaken or reverse that channel.

LayerRoPE generates these gains from a shared learned vector and the layer number. It scales the vector’s length with a magnitude schedule and rotates pairs of gain entries with a rotation schedule. The resulting gains multiply the activations channel by channel. The rotation operates on the gain vector, rather than directly rotating the residual state or cached keys and values. See the LayerRoPE construction.

Each block reads the state and adds an update. The baseline uses ordinary learned input-normalization gains.

LayerRoPE

Depth-dependent channel gains

The input and output controls depend on the layer number. A shared gain vector replaces independent vectors at every layer.

mHC

Four residual streams

Manifold-constrained Hyper-Connections learn how to read, carry and write multiple streams. The carry mixer is normalized toward row and column sums of one, using 20 finite Sinkhorn iterations here. LayerRoPE can also gate the block inside this routed model.

Two beta knobs, at both input and output

βmag sets how gain magnitude changes with depth. βrot sets how the rotation angle changes with depth. They are separate parameters. The measured sweep starts both at the same value, −1, −0.5 or 0, at all four sites; training can then change each independently.

At initialization, a more negative magnitude beta makes deeper layers’ gains smaller. A more negative rotation beta makes their rotation angles fall faster with depth. Input gains control what a block reads; output gains control the update it writes back.

The exact schedules and the remaining knobs
Depth d = 1, 2, …, 32 Magnitude multiplier m(d) = exp(α_mag) × d^β_mag Rotation angle θ(d, j) = exp(α_rot) × d^β_rot × 100^(−2j / width) Effective gain pair = m(d) × Rotate(shared gain pair, θ(d, j)) Apply the resulting real gains channel by channel.

The learned α intercepts set the overall magnitude and angular scale. The shared gain vector sets the channel pattern. The frequency base, 100 here, spreads the rotation across pairs; it is fixed in this sweep. Every input/output site has its own parameters.

With zero intercepts at layer 16, β=−1 gives magnitude 1/16, β=−0.5 gives 1/4, and β=0 gives 1. The first pair’s angles are respectively 1/16, 1/4 and 1 radian. These examples describe initialization. They do not determine the learned residual variance or guarantee better quantization.

QKNorm helps mHC here; residual still leads at equal time

Query-Key Normalization (QKNorm) improves mHC clean loss in all three paired seeds at 787 seconds, from 2.722623 to 2.653771 nats on average. Ordinary residual without QKNorm remains best at the same time budget, at 2.280066. This is a new, separate three-seed screen: all 24 models trained from scratch, with QKNorm off/on for each architecture. It does not continue or pool the earlier eight-seed experiment.

QKNorm normalizes each query and key vector to unit length, then learns a scalar that controls attention-score strength. Values stay unchanged. This changes how attention matches tokens. LayerRoPE changes depth-dependent gains, and mHC changes residual-stream routing; these are separate controls.

Does it enable stronger cache quantization?

No smaller usable cache format emerges at equal training time. The own-clean rule permits at most 0.1 nat extra CE relative to that checkpoint’s clean loss. Its minimum ideal cache cost remains 3,072 bytes per cached token for every architecture, off or on, at both endpoints. A pass allows this stated damage; it does not mean unchanged quality.

The common-quality rule instead compares every architecture with the same paired residual/off clean reference, plus 0.1 nat, at the same endpoint. One fixed policy must pass all three seeds. That gives the following minimum ideal costs:

K3/V3 versus K3/V2: inspect both endpoints

K3/V3 is the reference for lowering V alone from three to two bits while holding K at three. Both use the same signed codebook rule; unequal K/V widths are a separate choice from signed versus affine quantization. K3/V3 costs 3,584 ideal bytes per token and K3/V2 costs 3,072.

Screen method, runtime and limits

The model has 32 layers, width 128, two 64-channel attention heads, feed-forward width 352, context length 256 and the GPT-2 vocabulary. Rates for residual, LayerRoPE, mHC and the combination are 0.001, 0.01, 0.003 and 0.01. Off/on pairs share common initial weights and token order. AdamW uses (0.9, 0.95), epsilon 10−8, zero decay and no clipping; warmup lasts 100 updates, then the rate stays constant.

One 80GB CUDA GPU runs one worker at a time, using Python 3.12.11, PyTorch 2.9.1+cu128, FlashAttention and four CPU threads. Master parameters, normalization, routing and optimizer state are FP32; matrix operations use BF16. TF32 and compilation are disabled. QKNorm accumulates norms in FP32 with epsilon 10−12. One unconstrained FP32 scalar per attention module is shared across heads, initialized to log2(256²−256), cast to the query dtype and multiplied into Q; attention uses scale 1.

The training clock includes batch preparation, transfers, forward/backward, optimization and scheduled checks. Setup, offline validation, attention diagnostics and checkpoint writes have separate clocks. Fresh validation and final documents exclude 184,656 recorded exact-text predecessor hashes. Validation has 32,768 targets; the final holdout has 131,072. Exclusion does not detect paraphrases. The final holdout opens only after all training statuses close.

All 24 trajectories and 480 cache cells completed, with no numerical failures. Ninety-six scientific checkpoints retain model, optimizer, random-number-generator, cursor and clock states; exports were hash-verified before compute teardown. The ten frozen policies are clean K16/V16, signed K3/V16, K2/V16, K16/V3, K16/V2, K3/V3, K3/V2, K2/V3, K2/V2, and affine K2/V2. K16/V16 leaves the BF16 cache unchanged. Rounding is token-local, once on write; no packed cache or quantization-aware training ran.

mHC keeps its original 20 finite Sinkhorn iterations, epsilon, precision and operation order. Completion does not clear the separate routing-tolerance findings. Offline attention statistics reconstruct FP32 reference scores and do not expose bit-exact fused BF16 internals. Three seeds, inherited rates, narrow width and short context limit the finding; no population winner, equivalence or causal explanation is established.

No candidate passed the declared numerical screen. A saved-checkpoint replay compared 20, 40, 80, 160 and 320 normalization iterations in FP32 and FP64, using identical captured FP32 router logits. Small column errors, passing derivatives and finite values do not prove that every routing constraint or a longer training trajectory is stable.

Finite normalization misses the stricter audit tolerance. The mHC paper uses 20 iterations as a practical approximation and discusses remaining gain deviations. The pinned reference has epsilon and a final column normalization; its default is 10, while this experiment explicitly uses 20. Our 10−4 gate is not an upstream guarantee. An exact doubly stochastic constraint would require both row and column sums to equal one.

The conditional pilot was not admitted. No changed-operator full-forward sensitivity test or new training intervention ran. No new learning-speed or quantization effect follows. A lower violating fraction for the combination in these examples does not establish an advantage across seeds. The iteration grid, epsilon, tolerance and failed matrices were retained unchanged. K3/V2 uses three bits for keys and two for values; K3/V3 is the matched three-bit comparison. “Signed” means a zero-centered quantizer, even when key and value bit widths differ. An affine quantizer adds an offset so its range need not be centered on zero.

Measure distribution shape, rather than assume a mechanism

Magnitude and rotation change the learned network, but a larger residual variance is not itself a compression benefit. The absmax scale can absorb a uniform amplitude change. Relative rounding error, downstream loss and total bytes decide whether a change is useful.

The negative-beta models have lower final residual variance here, rather than a uniform increase. Plain β=0 LayerRoPE has a large spread across seeds. These small, short-trained models do not reproduce a general residual-widening mechanism. No magnitude-only, rotation-only or isolated output-gain ablation was run.

MNIST: no variant met the transfer-suppression rule

The separate digit experiment freshly trains fourteen configurations with ten paired seeds each: residual, Hyper-Connections (HC), mHC, their full input/output LayerRoPE beta variants, and two input-only comparison rows. A teacher learns digits; a student then imitates only its auxiliary outputs on random noise. Transfer is the student’s digit-accuracy gain above its own initialization.

None of the nine full-gain-versus-parent comparisons passes the frozen suppression rule. Mean transfer changes span −2.283 to +4.251 percentage points. Wide intervals leave useful effects unresolved. The adaptation uses four width-256 MLP blocks, five teacher and 80 student epochs, FP32 and Adam at 0.0003. It retains LayerNorm centering and bias.

Trained mHC routing misses the tracked stability limit. The baseline and all three full-gain mHC rows exceed the 10−4 row/column error threshold in tracked training/control paths. The largest column error approaches one. Auxiliary-only shared-initialization paths stay below the limit, but the frozen gate covers all tracked paths. Numerical operator qualification does not clear this trained-constraint failure. These observations do not establish a subliminal-learning defense.

Paired suppression comparisons and decision rule

A candidate needs at least five percentage points less mean transfer, a paired interval wholly below zero, preserved teacher and all-output accuracy within two points, acceptable convergence, and tracked routing stability. Intervals use confidence 1−0.05/9 (99.44%) and 100,000 bootstrap resamples across all ten seeds.

What the fixed-token measurements cover

The language models have 32 layers, width 128, two attention heads, feed-forward width 352, a 256-token context and the GPT-2 vocabulary. Residual/LayerRoPE models have about 19.3 million parameters; mHC variants have about 20.1 million. Each final model receives 2,000 updates of 2,048 predicted tokens. Each row first receives four 500-update learning-rate pilots at 0.0003, 0.001, 0.003 and 0.01. Mean pilot CE at updates 300/400/500 selects the rate; ties select the smaller rate.

Final seeds 77311–77313 pair common initial matrices and training-token orders across configurations. Every model starts fresh; none continues an earlier trained checkpoint. The data preparation and evaluation arrays are reused with hash checks, so the three-seed results are descriptive evidence, not independent confirmation.

Measurements use two matched 80GB GPUs, Python 3.12.11, PyTorch 2.9.1 and four CPU threads per worker. Master weights, optimizer state, normalization, gains, routing and CE use FP32. Language matrix operations use BF16; TF32 and compilation are disabled. AdamW uses (0.9, 0.95), epsilon 10−8, no weight decay or clipping, and 100 warm-up updates followed by a constant learning rate.

Quantization runs after training on unchanged final checkpoints. Each receives fourteen weight/input/residual policies and 51 cache cases: clean, the 16/8/4/3/2-bit K/V grid for signed and affine quantizers, and FP4/FP8 cache cases. Scales and metadata enter ideal byte counts. No native packed-kernel, measured serving-memory or throughput benefit follows from these simulations.

Measured source: knlp 17035f84. The experiment protocol defines the gains, controls, quantization scopes and retained checkpoints.

Reproduce the comparisons

The standard Make presets run the fresh beta matrix and its post-training evaluations. The CPU smoke checks the actual gain, checkpoint and quantization paths on synthetic inputs; it cannot produce a scientific result.

make defconfig-layerrope-mhc-beta-smoke
make

The full preset requires an existing suitable two-GPU allocation and the pinned runtime. It runs GPU numerical checks, timing probes, learning-rate pilots, fresh language/MNIST training and quantization evaluation. It does not rent compute.

make defconfig-layerrope-mhc-beta
make CONFIG_RESIDUAL_OUTPUT_DIR=/path/to/runs \
     CONFIG_RESIDUAL_CHECKPOINT_DIR=/path/to/checkpoints \
     CONFIG_RESIDUAL_CPU_PYTHON=/path/to/python

Install dependencies from the reproduction guide. Use make menuconfig for external data/cache locations and runtime settings. Language checkpoints retain model, optimizer and random-number-generator states at updates 0, 1000 and 2000; pilot endpoints and MNIST teacher/student states are also retained. Generated reports, arrays, logs and checkpoints stay outside the source checkout.

Equal-training-time comparison

The separate time-budget presets retain the complete-update clock, held-out data preparation, bounded qualification, paired training and endpoint evaluation. QKNorm: training and saved-checkpoint evaluation

The three QKNorm presets use the same standard Make flow. The CPU smoke runs all eight architecture/off/on arms and all ten cache policies on synthetic tokens. It checks attention, gradients, pairing, exact resume and cache parity; it does not produce scientific results.

make defconfig-layerrope-mhc-qknorm-smoke
make CONFIG_RESIDUAL_OUTPUT_DIR=/path/to/qknorm-smoke

The QKNorm reproduction guide explains how to prepare document-excluding training/validation data, the separate final holdout, a hashed seed audit and the frozen run card. Finite-routing replay

The CPU smoke uses synthetic inputs and produces no scientific finding. Exact replay requires six recorded qualification checkpoints and a generated input manifest. The routing-input guide provides the schema, public data preparation, explicit qualification commands and an executable manifest generator for your own checkpoints. Regeneration creates a new experiment; another runtime may reject the strict original-loss fidelity check.

make defconfig-layerrope-mhc-routing-audit-smoke
make
python -m research.layerrope_beta.time_budget.routing_inputs manifest \
    --data /path/to/training \
    --result /path/to/M/RESULT.json --result /path/to/ML/RESULT.json \
    --out /path/to/AUDIT-INPUTS.json
make defconfig-layerrope-mhc-routing-audit
make CONFIG_RESIDUAL_AUDIT_INPUTS=/path/to/AUDIT-INPUTS.json

The audit stops after its candidate decision. It does not enqueue a training pilot, a solver extension or another quantization sweep. All generated manifests, checkpoints and raw results stay outside the source checkout.
