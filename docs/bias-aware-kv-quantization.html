Bias-aware FP8 repairs retrieval.
Its serving cost is too high.

Can we fix the key-quantization failure, keep both keys and values in FP8, and make the correction fast enough to serve? The tested pre-bias representation repairs retrieval. Its optimized kernel delivers 35% fewer completed requests per second than asymmetric K16/V8 in the equal-memory test, with 2.06× p95 request latency.

This page covers that closed pre-bias experiment. Current asymmetric K16/V8 results, supported models, and installation are on the asymmetric quantization guide.

The representation repairs the tested failure

Ordinary FP8 key storage destroys long-context retrieval on the tested Qwen2.5-7B model. Pre-bias stores bias-removed keys in FP8 and restores the position-dependent bias contribution inside attention. Values also remain in FP8. The correction recovers the information that ordinary key quantization loses.

The optimized correction also passes all eight clean mutation-test cases at the model's attention geometry; injected defects that affect that kernel are detected. Pre-bias provides 1.50× the measured KV token capacity of K16/V8.

These results establish retrieval rescue and tested kernel correctness. They do not establish general quality equivalence. The 200-problem GSM8K math screen reports 45.5% for pre-bias and 49.5% for the 16-bit reference; only aggregate scores were retained, so paired outcome analysis cannot be recovered.

More capacity does not produce more served work

The final test gives each method the same memory budget, then compares its capacity point: 32 concurrent requests for K16/V8 and 48 for pre-bias. It uses Qwen2.5-7B on one H100, identical seeded prompts, 30,720 input tokens and 128 fixed output tokens. Both arms use FlashInfer's generic kernel family.

The optimized pre-bias kernel fails both serving conditions.Pre-bias remains near 0.43 requests per second at concurrencies 16, 24, 32, and 48. The sweep points to a prefill bottleneck: extra cache capacity adds waiting without increasing completed work.

Separate kernel measurements also show a cost: pre-bias takes 1.687× the 16-bit-key kernel time at 4,096 tokens and 1.107× at 32,768 tokens. Five fresh processes confirm the pattern at the served geometry. Smaller storage alone does not guarantee faster attention.

The serving evidence contains two agreeing interleaved blocks, rather than the five planned repetitions. Both throughput and latency miss their bounds by wide margins, so the review accepts the negative engineering decision. This is not a five-repetition performance certification or a claim about every future bias-aware implementation.

Evidence and scope

The served geometry is 28 query heads, 4 key/value heads, and rotary base 1,000,000. The measured source versions are vLLM 8a1714108 and FlashInfer 6dfdc833. These are the experimental pre-bias versions, not the current asymmetric installation recipe.
