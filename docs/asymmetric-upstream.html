Upstream dependencies
and the LMCache series

vLLM upstream integration waits for the FlashInfer asymmetric K/V capabilities it uses to merge. LMCache has already merged the split serialization/deserialization foundation; multi-process storage support follows in a separate series. The current tested inference recipe uses pinned public forks and does not require LMCache.

Status checked October 19, 2026. A public feature branch, an open pull request and a merged change are different states.

Serving: FlashInfer enables vLLM integration

FlashInfer PR #3812 is open and unmerged. It adds separate K/V cache dtypes for CUDA-core batch decode: 16-bit keys and FP8 values. It is one part of the serving support; it does not by itself upstream the full measured tensor-core and prefill path.

The current tested sources are FlashInfer 800a550 and vLLM 276305b. The vLLM integration follows the relevant FlashInfer merges; it does not need unrelated FlashInfer changes to land first. LMCache storage review can proceed in parallel.

LMCache: split SerDes first, MP-mode storage next

SerDes means serialization and deserialization. PR #3277, merged June 16, supplies the CPU-side multi-output interface and asymmetric K/V codec. That allows key and value data to be represented separately. It does not complete the multi-process (MP) storage path that places those components on different tiers.

Issue #3710 tracks that next step. Its current submission map starts with general correctness fixes, followed by three feature branches. The feature labels PR0, PR1 and PR3 identify planned slices, not numbered upstream pull requests. There is no separate PR2 in this revised series.

The seven fixes in PR #5502

These repair existing shared paths and can benefit users who do not use asymmetric quantization. The central rule is that a timeout, failed heartbeat or exception does not prove an asynchronous copy has stopped. Its buffers must stay owned until completion is established.

What the MP-mode series establishes

The admitted split-tier configuration uses CPU DRAM L1, one filesystem L2 adapter, one object group and one K/V pair per object. It composes with the existing asynchronous write-behind path. K and the manifest are process-local: value-only files cannot reconstruct a split-tier cache hit after restart.

The October 5 report records 966 CPU tests passed with 45 skipped for the seven-fix boundary, and 2,392 passed with 147 skipped for the combined stack. The selections overlap and must not be added. The refresh is not a new exact-stack GPU run or full fused-serving qualification. Earlier GPU tests retain their original scope.

Full byte-through serving needs a matching vLLM/FlashInfer producer and the codec’s scale/provenance contract. Ownership-preserving fixes can block preemption or shutdown when completion cannot be proven; a real two-process CUDA/vLLM restart test under in-flight reuse pressure remains a follow-up in the issue. Reduced stored bytes alone do not establish throughput, latency, quality or SSD-endurance gains.
