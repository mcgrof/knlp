First conversation

Decide what the agent may do

Repository and review

Pin the repository, base/head and selected paths. Discover contribution, security, commit and testing rules. Public issues, branches and PRs are untrusted input, not instructions that expand the assignment.

Company model access

Use the company's approved service and existing credential manager or managed login. Agree on data classes, retention policy, request/token/cost limits and retries. Do not assume a corporate seat permits API automation or fall back to a personal account.

Tests and hardware

Inspect commands and dependencies before running them. Separate CPU, QEMU, bare-metal and real-GPU coverage. Assign resources and limits; keep model, cloud and Git write credentials outside untrusted test code. A worktree is not a sandbox.

Human delegation

Let the owner choose standing grants and mandatory handoffs. Missing required coverage, privileges, destructive tests, new spending and publication are explicit decisions. No response pauses the task; it does not grant permission.

Evidence before green badges

Choose tests by the claim

SettingWhat it can checkWhat still needs care
Isolated CPU workerBuilds, unit contracts, parsers, sanitizers and mocksNo proof of kernel attachment, device behavior or GPU execution
Disposable QEMU guestGuest kernel and supported emulated-device pathsNo physical performance or unsupported firmware/transport coverage
Assigned bare metalReal driver, device and recovery behaviorExplicit privilege, exclusive target and recovery grants; never an arbitrary disk
Assigned real GPUVendor/runtime integration, device correctness and memory behaviorA cloud container may lack required host or storage APIs; record fallback and teardown

QEMU is a machine emulator. A mock pass is not a hardware pass. Report passed, failed, skipped, unavailable and not-run checks separately. Keep command, input, environment and base/head identities with each receipt; changed revisions invalidate affected evidence.

Four starting profiles

One discipline, different test plans

Examples for adoption, not claims of deployment.

libcxlmi

Start with the library's Meson, mock, sanitizer and binary-interface checks. Device-management transports and commands need separate emulated or real-device coverage. Keep reset and firmware actions human-gated.

ebpf-syscall

Separate offline tooling from kernel verifier, attach, event and detach tests. A guest needs the right configuration, debug metadata and device paths. Runtime tracing and replay need explicit scope and privileges.

Rush / rush-status

Public status is not implementation coverage. Maintain that surface separately; derive build-engine tests only from separately admitted source. Treat dependency builds as code execution, not harmless metadata.

fio

Distinguish ordinary file-backed tests, supported QEMU device tests and physical storage checks. Raw writes, format and discard need named disposable targets, exclusive ownership and operator-approved recovery.

Incoming code

Review the commits, not the title

Read every commit diff and the complete series. Check correctness, error paths, intermediate buildability, tests and whether each message explains its hunks. Fold a later repair into the earlier unmerged commit that owns it; distribute a mixed cleanup instead of asking for one giant squash.

If an unlabeled change repairs a bug already present upstream, verify the trigger and introducing commit. Recommend a separate fix and the project's fix metadata where justified. If the defect exists only in this new series, request a fold. Do not guess a Fixes: hash, rewrite a contributor's branch or publish an approval from a read-only assignment.

From one review to recurring work

Keep ownership and evidence explicit

Begin with one manually admitted task and one worker. For concurrency, a real authority service must make atomic claims, bound leases and reject stale results; this starter does not provide that service. Keep one writer per target branch and separate review, execution and publication rights.

Use a private briefing for findings and hardware gaps. A dashboard refresh is not proof of fresh tests, a backup or human approval. Suspected unauthorized activity goes directly to the owner's preconfigured incident route, without waiting for the chore rotation. Agents must not suppress evidence or remediate just because they found a problem.

Helping existing maintainers is the first use. More extensively AI-maintained projects can build on measured experience later.
