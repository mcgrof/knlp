A working adaptation

From a paper queue to tested cache contracts

A research use case within a broader task framework.

We have successfully used an adaptation of Chores for Prefix Integrity Analysis (PIA): checking whether a transformed KV-cache object remains safe to restore and share. The AI Post Transformers paper queue supplies candidate research. Scoped Chores tasks turn relevant papers into primary-source reviews and small, reproducible CPU experiments.

  1. DiscoverMatch a queued paper to an active question and retain its source revision.
  2. InspectRead the mechanism, define the saved object and check prior evidence.
  3. Test on CPUUse Cartridge geometry and a block manifest to check identity, selection and layout.
  4. ReviewKeep inputs and verdicts; identify any model or serving question that remains.

Finding · prefix identity

SnapStream

Query-dependent selection makes a prefix-only cache key unsafe for cross-query reuse. Adding query identity resolves the collision; compact layout, logical positions, padding and mutable ring state still require a method-aware connector.

Finding · backing history versus selected reads

HiSparse

The complete backing prefix passes the CPU contract model. Selected reads are request-time routing; saving only them under a prefix-only key fails the misuse control. That is a reuse mistake, not a defect in the complete-history design.
